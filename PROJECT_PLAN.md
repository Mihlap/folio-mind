# План проекта: Folio Mind (PDF + ИИ)

## 1. Зачем этот проект

### 1.1 Цель

**Folio Mind** — платформа для **полного цикла** работы с PDF-документами, а не один экран «открыть файл». Ориентир по охвату — класс продуктов вроде **Adobe Acrobat**, плюс **встроенный ИИ**, которого у Acrobat нет в таком виде.

**Зрелый продукт должен закрывать:**

| Направление | Содержание |
|-------------|------------|
| Документ | Просмотр, версии, ACL, аудит, хранение в S3 |
| Операции | Сборка, правки, конвертация PDF ↔ Office |
| Подпись | Визуальная → PAdES/PKCS#7 (отдельный трек) |
| ИИ | Аудит рисков, правки с подтверждением, чат, RAG по регламентам |
| Презентации / буклеты | Проект и медиатека, макет изображений, согласование с заказчиком, пресеты выгрузки и контроль качества (DPI, водяные знаки) |

### 1.2 Сценарий v1 (фокус разработки)

1. Загрузка договора PDF → 2. Просмотр (PDF.js) → 3. ИИ-проверка рисков → 4. Отчёт + чат.

**Готово v1:** файлы 10+ МБ, превью в фоне, ИИ на GigaChat или YandexGPT, журнал действий.

### 1.3 Принципы

- **Позиционирование:** Acrobat-class + AI-native workflow, не клон UI Acrobat.
- **ИИ:** предлагает; подпись/отправка — только по явному действию пользователя.
- **PDF:** без своего движка (§3.3).

**Целевые платформы распространения:**

| Платформа | Подход |
|-----------|--------|
| **Web** | Один код на **все размеры экрана**: от смартфонов до ultra-wide. Браузеры: Chrome / Edge / Safari / Firefox; на мобильных — **Mobile Safari (iPhone, iPad)** и **Chrome / браузеры на Android** |
| **Android (нативная установка)** | Тот же **React**-интерфейс упакован через **Capacitor** в **установочный пакет APK** (и для магазинов — **AAB**): пользователь скачал → установил → приложение открылось в системном WebView. **Один** фронтовый код с веб-версией |
| **Смартфон (без установки)** | В браузере или **PWA** «на домашний экран» — как дополнительный канал; учёт **safe area**, жестов zoom/scroll в viewer, крупные зоны нажатия |
| **Планшет** | Адаптивные breakpoints; на Android при желании тот же **APK** на планшет; на iPad — браузер / PWA (параллельный трек **iOS через Capacitor → IPA**, если понадобится магазин Apple) |
| **ПК (Windows / macOS / Linux)** | Только **веб-приложение в браузере** — отдельная **настольная .exe/.dmg-оболочка в плане не используется** |

## 2. Область продукта (Scope)

### 2.1 Базовый контур (ядро — документ; ИИ расширяет ценность)

| Направление | Описание |
|-------------|----------|
| Просмотр | Навигация, масштаб, миниатюры, поиск по тексту, оглавление, закладки, доступность |
| Создание / сборка | Слияние PDF, разбиение, вставка/удаление страниц, шаблоны, изображения → PDF |
| Редактирование | Текст/изображения (в рамках возможностей формата), водяные знаки, штампы, базовая разметка |
| Формы | AcroForm: заполнение, валидация, экспорт данных (поэтапно) |
| Подпись | Простая (визуальная) → усиленная: PKCS#7/PAdES, цепочки доверия, штампы времени |
| Конвертация | Импорт/экспорт (Office, изображения); очереди, повторы, SLA |
| Метаданные / права | Версии, ACL, журнал действий, retention, экспорт аудита |

### 2.2 Слой ИИ (расширяет возможности сильнее классического Acrobat)

| Возможность | Смысл для пользователя |
|-------------|------------------------|
| **Аудит документа** | Риски, противоречия, пропуски разделов, сравнение с политикой |
| **Исправления** | Предложения правок с обязательным подтверждением человеком |
| **Редактор-помощник** | Перефразирование, унификация терминов, стиль |
| **Извлечение знаний** | Сущности (даты, суммы, стороны), таблицы → структурированные данные |
| **Конвертация + смысл** | Сохранение логической структуры, а не только «файл в файл» |
| **Сценарии** | Чат по документу, RAG по базе шаблонов и регламентов |

**Принцип:** ИИ **предлагает и черновит**, критические действия (подпись, отправка, публикация) — **только после явного действия пользователя** и логирования.

### 2.3 Сценарий для архитекторов (буклеты и презентации)

Отдельный ICP: архитектурные бюро и проектировщики. Типовой документ — **буклет / альбом**: много **растровых изображений** (рендеры, планы, фото объектов), мало текста. Цель — **не гонять файлы по почте и мессенджерам** («скачай → сожми → перекинь»), а собрать, оформить и отдать заказчику **из одного места**.

| Боль (как сейчас в Acrobat и аналогах) | Решение в Folio Mind |
|----------------------------------------|----------------------|
| Обрезка фото и **позиционирование картинки на листе** | Режим макета: crop, drag/resize, привязка к сетке и полям страницы; сохранение в новую версию PDF |
| Нет **линеек и направляющих** (как в Photoshop) | Линейки (мм/см), направляющие, snap к краям и центру листа; опционально сетка |
| У заливок **нет прозрачности и градиентов** | Палитра с alpha; линейный/радиальный градиент для фигур и подложек; при экспорте — flatten в PDF через worker |
| **Общий доступ с заказчиком** отсутствует | Ссылка «только просмотр»; роль «комментатор» без права править; роль «редактор» для своей команды; поток без скачивания исходника |
| Постоянное **сжатие вручную** перед отправкой | Пресеты выгрузки: «для почты», «для печати», «максимальное качество»; джоба на worker (qpdf/Ghostscript, пересжатие изображений) |

Дальше — не отдельный продукт, а **расширение того же сценария**: меньше ручной рутины вокруг файла, больше «проект → версии → ссылка заказчику».

| Контур | Что даёт бюро | Фаза |
|--------|----------------|------|
| **Проект и материалы** | Папка проекта (несколько PDF и вложений), именованные версии («черновик», «на согласовании», «финал»), сравнение двух версий страница к странице; **медиатека** рендеров и фото — вставка в буклет без повторной загрузки; **шаблоны бюро** (логотип, поля, типовые развороты A4/A3) | **2b** |
| **Макет и страницы** | Перестановка и дублирование страниц; выравнивание нескольких картинок; замена изображения «на месте»; лёгкая коррекция яркости/контраста; колонтитулы и нумерация; **режим презентации** (полноэкранно по страницам); внутренние пометки (стрелки, рамки), скрываемые при экспорте «для заказчика» | **2b** |
| **Согласование с заказчиком** | Watermark «Черновик / не для печати» на просмотре по ссылке; срок и пароль ссылки, отзыв; статусы **черновик → на согласовании → утверждено**; комментарии с @упоминаниями; отметки страниц «ОК / нужны правки»; уведомления (email / опционально Telegram) о новых комментариях | **2b** |
| **Экспорт и контроль** | Пакет «PDF + превью страниц (JPG)» по одной ссылке; экспорт отдельных страниц в PNG/JPG; **чеклист перед печатью** (DPI, встроенные шрифты); PDF/A для архива — по запросу | **3** |
| **Объект и мобильность** | Фото с телефона → в медиатеку проекта; офлайн-просмотр последней версии на площадке; визуальное «согласовано» с планшета (подпись-штамп) | **4** |

**ИИ (лёгко, поверх буклета):** автоподписи к рендерам из имени файла/метаданных; черновик текста для титульника; поиск по материалам проекта («где в буклетах план парковки»). Не заменяет BIM/CAD.

**Сценарий v1.1 (архитекторы, после v1 юристов):** проект «объект X» → медиатека и шаблон → сборка буклета (макет, crop, линейки) → пресет сжатия → ссылка заказчику (watermark, только просмотр) → комментарии и статусы согласования → правки → финал с чеклистом DPI → выгрузка.

**Ограничение:** не InDesign/Photoshop и не AutoCAD/Revit в браузере; **CMYK-допечатка и одновременное редактирование «как Google Docs»** — вне v1–v3. Фокус: **PDF-буклет с картинками**, предсказуемый экспорт и цикл согласования без «скачай и перекинь».

### 3.3 PDF: стратегия без собственного движка

**Принцип:** собственный парсер/рендер PDF **не разрабатываем**. Folio Mind — **композиция проверенных движков** + **свой продуктовый слой** (viewer, ACL, версии, S3, очереди, ИИ, подпись, аудит). «С нуля» пишем только **UX и бизнес-логику**, не низкоуровневую работу с форматом PDF.

```
┌──────────────────────────────────────────────────────────────────┐
│  Слой Folio Mind (свой код)                                       │
│  packages/ui (viewer), Redux, API, ACL, версии, S3, ИИ, подпись  │
└───────────────────────────────┬──────────────────────────────────┘
                                │
        ┌───────────────────────┼───────────────────────┐
        ▼                       ▼                       ▼
   Просмотр                 Лёгкие правки          Генерация отчётов
   PDF.js                  pdf-lib                @react-pdf/renderer
   (опц. react-pdf)        (клиент)               (только worker/API)
        │                       │                       │
        └───────────────────────┴───────────────────────┘
                                │
                    Тяжёлые операции (apps/worker)
                    qpdf + Ghostscript → S3 processing/
```

#### 3.3.1 Зафиксированный стек по задачам

| Задача | Инструмент | Где выполняется |
|--------|------------|-----------------|
| **Просмотр** существующих PDF | **PDF.js** (`pdfjs-dist`); опционально обёртка [wojtekmaj/react-pdf](https://github.com/wojtekmaj/react-pdf) | Клиент: `packages/ui`; тот же код в Capacitor WebView |
| **Лёгкие операции** (merge/split страниц, простые аннотации) | **pdf-lib** | Клиент; результат → новая версия в S3 |
| **Превью страниц, извлечение текста, конвертация, repair** | **qpdf** + **Ghostscript** | `apps/worker`, изолированные контейнеры; I/O только S3 |
| **Генерация PDF** (отчёт ИИ-проверки, шаблонные акты) | **@react-pdf/renderer** ([diegomura/react-pdf](https://github.com/diegomura/react-pdf)) | Worker/API → файл в S3 `exports/` |
| **Резерв генерации** (если не хватит layout у renderer) | **PDFKit** (Node) | Только worker, по необходимости |
| **Текст для ИИ / RAG** | Тот же пайплайн, что превью/индексация | Worker → S3 или Postgres (метаданные + ссылка) |
| **Подпись PAdES / PKI** | Специализированные библиотеки или внешний подписант (HSM, DSS) | Отдельный трек, не в viewer |

#### 3.3.2 Две разные «react-pdf» (не путать)

| Репозиторий | Пакет | Назначение в Folio Mind |
|-------------|--------|-------------------------|
| [wojtekmaj/react-pdf](https://github.com/wojtekmaj/react-pdf) | `react-pdf` | **Показать** PDF (обёртка над PDF.js). Опционально на v1 для ускорения старта |
| [diegomura/react-pdf](https://github.com/diegomura/react-pdf) | `@react-pdf/renderer` | **Создать** новый PDF из React-компонентов. Только отчёты/экспорт, **не** редактирование чужого договора |

#### 3.3.3 Что сознательно не используем на v1

| Решение | Причина отказа |
|---------|----------------|
| **Свой PDF-парсер/рендер** | Годы разработки, риски совместимости; не ценность продукта |
| **Несколько viewer-движков** (PDF.js + EmbedPDF/PDFium + Syncfusion одновременно) | Разный рендер, тяжёлый бандл, сложная поддержка |
| **EmbedPDF / PDFium** | Только после замеров, если PDF.js не тянет на целевых файлах |
| **Syncfusion React PDF Viewer** | Тяжёлая зависимость и лицензионные ограничения; не ядро v1 |
| **[wonday/react-native-pdf](https://github.com/wonday/react-native-pdf)** | Для **React Native**; у нас **Capacitor + общий React-web**, viewer — PDF.js в WebView |

#### 3.3.4 Свой код (граница ответственности)

| Компонент | Содержание |
|-----------|------------|
| `packages/ui` | Toolbar, thumbnails, zoom, safe-area, интеграция с `viewerSlice`, presigned stream |
| `packages/pdf-contracts` | DTO операций, статусы джоб, типы версий |
| API + worker | Оркестрация S3, очереди, ACL, аудит; **без** reimplementation PDF spec |
| ИИ-слой | Промпты, grounding, accept/reject правок поверх извлечённого текста |

*Лицензии PDF, шрифты, патентная чувствительность — чеклист в Фазе 0 (`docs/PDF_LICENSES.md` или раздел в ROADMAP).*

### 3.4 Хранение больших объёмов данных (S3)

Все **бинарные и крупные артефакты** — только в **S3-совместимом object storage**, не в Postgres и не на диске API-контейнера.

| Bucket / префикс | Содержимое | Политика |
|------------------|------------|----------|
| `originals/` | Исходные PDF по версиям | Версионирование bucket или immutable key + metadata в БД |
| `previews/` | Миниатюры страниц, PNG/WebP | TTL по настройке tenant; пересборка из originals |
| `processing/` | Промежуточные файлы воркера (распаковка, конвертация) | Короткий TTL (например 24–72 ч), lifecycle rule |
| `exports/` | Отчёты проверки, экспортированные Office/PDF | ACL по пользователю; ссылка presigned |
| `rag-sources/` | Загруженные шаблоны/регламенты (если не только текст в БД) | Шифрование at-rest по требованию заказчика |
| `media/` | Исходники медиатеки проектов (рендеры, фото с объекта) — для буклетов §2.3 | ACL по проекту; lifecycle по tenant |

**Окружения:**

| Среда | Хранилище |
|-------|-----------|
| **dev** | **MinIO** в Docker Compose (S3 API) |
| **prod** | Облачный **S3** заказчика: AWS S3, **Yandex Object Storage**, VK Cloud, Selectel и т.д. — один SDK (**@aws-sdk/client-s3**) |

**Разделение Postgres и S3:**

| Где | Что хранится |
|-----|----------------|
| **Postgres** | Пользователи, tenant, ACL, метаданные документа, `s3Key`, размер, hash, статус джобы, аудит, короткий текст / индексы |
| **S3** | Тело PDF, превью, экспорты, временные файлы воркера, крупный извлечённый текст (при необходимости) |
| **Не в Postgres** | Бинарные PDF, изображения страниц, файлы > нескольких МБ |

**Практики:** multipart upload для файлов > 5–10 МБ; presigned URL для прямой загрузки/скачивания с клиента; server-side encryption (SSE-S3 или KMS).

### 3.5 ИИ: провайдеры по выбору заказчика

Заказчик при развёртывании задаёт **одного основного провайдера** (или fallback-цепочку в конфиге):

| Провайдер | Назначение | Интеграция |
|-----------|------------|------------|
| **GigaChat** (Сбер) | Чат, саммари, аудит, структурированные ответы | OAuth / API key, REST; пакет `packages/ai-providers/gigachat` |
| **YandexGPT** (Yandex Cloud) | Те же сценарии | Foundation Models API, folder_id + IAM; пакет `packages/ai-providers/yandex` |

**Единый контракт в коде:**

```ts
interface LLMProvider {
  complete(params: CompletionRequest): Promise<CompletionResponse>;
  embed?(text: string): Promise<number[]>;  // если RAG на эмбеддингах провайдера
  healthCheck(): Promise<boolean>;
}
```

Фабрика по env: `AI_PROVIDER=gigachat|yandex`. Промпты и схемы ответов — в `packages/ai-contracts` (не зависят от вендора). Логирование: request_id, модель, токены, **без** сохранения полного текста документа в логах (настраиваемо).

**Безопасность:** данные не уходят в обучение моделей (договорённости с вендором); опционально **on-prem / VPC** endpoint Yandex Cloud; для GigaChat — корпоративный контур API. Human-in-the-loop, grounding по фрагментам, Zod-валидация критичных JSON-ответов.

### 3.6 ИИ: качество и антигаллюцинации

- **Grounding:** привязка к фрагментам (страница, paragraph id).
- **Human-in-the-loop:** дифф, откат версий, журнал принятия предложений ИИ.
- **Режимы:** «только проверка», чеклисты для юр./фин. сценариев.
- **Кэш:** извлечённый текст документа в S3/Redis — не отправлять повторно в LLM без изменения версии.

### 3.7 Производительность и масштабирование

Стек **не меняем** — соблюдаем границы слоёв. Зависания при росте числа пользователей обычно из‑за тяжёлой работы в браузере, API или одного перегруженного worker, а не из‑за выбора Fastify/Node.

**Принцип SLA по слоям:**

| Слой | Целевое поведение | Запрещено |
|------|-------------------|-----------|
| **API (Fastify)** | Ответ < 300 ms: auth, ACL, метаданные, presigned URL, постановка джобы | Ghostscript, qpdf, сжатие, рендер всех превью, долгий LLM в HTTP |
| **Worker** | Всё CPU/IO-тяжёлое асинхронно, с таймаутом и лимитами tenant | Синхронное ожидание в API |
| **Клиент** | Просмотр через превью + виртуализация страниц; pdf-lib — только лёгкие правки | Сборка/сжатие буклета 50+ МБ в браузере |
| **S3** | Загрузка/скачивание напрямую (presigned); раздача превью через CDN | Проксирование PDF через API; хранение бинарников в Postgres |
| **ИИ** | Очередь `ai-jobs`, кэш по `documentVersionId`, лимиты токенов на tenant | Блокирующий HTTP 30–60 с на чат/аудит |

**Клиент (viewer и UI):**

- PDF.js: рендер **только видимых страниц** (±1–2), остальное — миниатюры из `previews/`; парсинг в **Web Worker**.
- Режим «лёгкий просмотр» для толстых буклетов: по умолчанию PNG/WebP из S3; полный PDF.js — по запросу.
- Списки документов: **пагинация курсором** + виртуализация; не держать PDF в Redux — только id и статус джобы.
- Статус джоб: polling с **exponential backoff** или SSE; не фиксированный `refetchInterval` у всех клиентов.

**API и БД:**

- API **stateless**, горизонтально 2+ реплики за балансировщиком.
- **Rate limit** per tenant и per IP: upload, export, AI.
- Prisma + **PgBouncer** в проде; индексы `(tenantId, updatedAt)`, `(documentId)`; без тяжёлых `OFFSET` на больших таблицах.

**Worker и очереди (BullMQ):**

- **Отдельные очереди:** `preview`, `optimize`, `convert`, `ai-index` — разный `concurrency`.
- **Лимиты tenant:** параллельные джобы, max размер файла, max страниц; идемпотентность по `jobId` + hash входа.
- **Таймаут/kill** subprocess Ghostscript/qpdf в контейнере; **N реплик** worker на один Redis.

**S3 и CDN:**

- **CDN** (CloudFront / Yandex CDN) перед `previews/` и статикой.
- Lifecycle на `processing/`, `media/` — обязательно в проде.

**Redis и Postgres:**

- Разделение назначений Redis: очереди BullMQ / кэш текста для ИИ / rate limit (отдельные DB index или инстансы при росте).
- **pgvector:** при нагрузке RAG — реплика или отдельная схема, чтобы поиск эмбеддингов не конкурировал со списками документов.

**ИИ:**

- Запросы GigaChat/YandexGPT — через очередь; UI получает статус и результат асинхронно.
- Circuit breaker при 429/5xx провайдера; fair-queue между tenant.

**Наблюдаемость (OpenTelemetry):**

- Метрики: p95 API, длина очередей, длительность джоб, ошибки Ghostscript, токены ИИ.
- Трейс `request_id` от API → worker → S3; алерты на рост очереди и 5xx.

**Ориентир масштаба (при соблюдении правил):** сотни одновременных **просмотров** (превью + CDN); десятки параллельных **тяжёлых** джоб — при 2–4 CPU worker и лимитах tenant. Узкие места: PDF.js на огромных буклетах, Ghostscript без лимитов, синхронный ИИ в API.

## 6. Риски и ограничения

| Риск | Митигация |
|------|-----------|
| Корректность ИИ в юр. документах | Human-in-the-loop, дисклеймеры, режим «только проверка» |
| Сложность редактирования PDF | Явные ограничения в UI; тяжёлое — worker (qpdf/GS), не свой парсер |
| Соблазн «написать свой Acrobat» | Зафиксированный стек §3.3; ценность — ACL, S3, ИИ, UX |
| Стоимость LLM | Кэш текста, лимиты tenant, выбор модели в конфиге |
| Лицензии PDF/шрифтов | Юридический чеклист до коммерции |
| WebView на Android | Матрица тестов, полифилы |
| Зависимость от одного облака ИИ | Абстракция `LLMProvider`, смена GigaChat ↔ Yandex без смены UI |
| Объём S3 | Lifecycle rules, мониторинг bucket size, квоты на tenant |
| Ожидания «как Photoshop/InDesign» у архитекторов | Явный scope §2.3; поэтапно: crop/линейки → градиенты → коллаб; не обещать CMYK и допечатку в v1 |
| Сложность overlay-редактора | Отдельный режим в `packages/ui`; тяжёлое flatten/сжатие — только worker |
| Раздувание scope буклетов | Жёсткая очередность: 2b.1–2b.4 → 2b.5–2b.7 → экспорт в 3 → mobile в 4; не смешивать с юр. v1 |
| Просмотр «висит» на толстых буклетах | Превью + CDN + виртуализация §3.7; pdf-lib/сжатие — worker |
| Перегруз worker (Ghostscript) | Очереди по типу, лимиты tenant, горизонтальное масштабирование §3.7 |
| Шторм polling статусов джоб | Backoff/SSE; не фиксированный refetch у всех клиентов |
| Синхронный ИИ в API | Только очередь `ai-jobs` + кэш по versionId §3.7 |
