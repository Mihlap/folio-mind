# Как посмотреть посещаемость

Это я написал для себя, чтобы не держать в голове порядок команд. Заходите по шагам,
как написано, и не спешите — команды короткие, каждая вводится отдельно.

Сразу главное: **ноль на счётчиках — это нормально.** Метрики поставили 1 октября,
и они считают только то, что происходит после этого. Истории до установки нет и взять её
неоткуда. Если хочется увидеть не ноль, зарегистрируйтесь на сайте и зайдите обратно.

## Что считается

Всё. Регистрация по email и вход по email с паролем. Вход по телефону, по ссылке из
письма и через внешние сервисы не считаются, для них счётчик останется нулевым.

Почты и IP-адресов в счётчиках нет. Сохраняется только что произошло, когда и
внутренний номер пользователя. Посмотреть по таким данным, кто чем занимался, нельзя.

## Заходим на сервер

Открываю PowerShell: клавиши `Win`, пишу `PowerShell`, Enter. Дальше:

```bash
ssh root@46.253.132.218
```

Пароль при вводе не показывается, это нормально. После входа появится приглашение
с решёткой, например `root@labatestvm:~#`.

Перехожу в папку проекта:

```bash
cd /root/pdf
```

## Смотрю цифры

Дальше одна команда, токен она берёт сама:

```bash
bash tools/metrics-table.sh 30
```

Тридцать в конце — это сколько дней показать, можно поставить любое число. Вывод такой:

```
Период: 2026-09-02 ... 2026-10-01
Регистрации: 12
Входы:       30
Активные:    12

День         Регистрации   Входы
2026-10-01             3      8
2026-10-02             9     22
```

Дни без событий пропускаются. Если событий не было совсем, будет строка
`(пока нет ни регистраций, ни входов)`.

## Делаю ссылку для браузера

В JSON смотреть неудобно, поэтому для показа кому-то делаю ссылку:

```bash
curl -s -X POST -H "Authorization: Bearer $(grep AUTH_METRICS_TOKEN apps/server/.env.prod | cut -d= -f2-)" -H "Content-Type: application/json" -d '{}' "http://127.0.0.1:3001/metrics/auth/share?days=30"
```

В ответе ищу поле `url`. Оно выглядит примерно так:

```
http://127.0.0.1:3001/metrics/auth/share/m:...:....abc?days=30
```

Ссылку копирую и открываю в браузере: три больших числа сверху, таблица по дням снизу.

Ссылка живёт сутки и сама отключается. В самой ссылке адрес `127.0.0.1`, поэтому из
браузера на рабочем компьютере она не откроется — надо заменить на адрес сервера. Если
так неудобно, смотрю цифры первой командой, они никуда не спешат.

## Если не получается

`command not found` или `No such file or directory` — я не в папке проекта. Возвращаюсь
к `cd /root/pdf` и повторяю.

Вместо цифр приходит 401 — команда не нашла токен. Проверяю, что файл на месте:

```bash
grep AUTH_METRICS_TOKEN apps/server/.env.prod
```

Если строка пустая, значит токен не прописан, и метрики закрыты для всех. Тогда надо его
задать — скажите, и я это сделаю.

Всё равно нули — скорее всего, после установки ещё никто не заходил. Регистрируюсь на
сайте через обычную форму, возвращаюсь, запускаю `bash tools/metrics-table.sh 7`.
Должна появиться единица.

## Про токен и ссылки

Токен — это по сути пароль от всей статистики проекта. В репозиторий его не коммичу,
в переписке не пересылаю. Если засветился — меняю и перезапускаю сервер.

Ссылка слабее токена: она только показывает цифры, ничего менять не позволяет. Удобно
кинуть коллеге. Но она открыта тому, кому я её отправил, и отозвать её нельзя — просто
истечёт через сутки.

Данные сервер чистит сам раз в сутки, всё старше 12 месяцев удаляется. Это же написано
в политике конфиденциальности, так что документ и реальность не расходятся.

## Где смотреть ещё

`pnpm metrics:auth` из папки проекта на своей машине — то же самое, но нужно, чтобы
сервер был виден снаружи. И `http://localhost:3001/docs`, если сервер запущен локально:
там кнопка Try it out и токен в поле Authorization.
