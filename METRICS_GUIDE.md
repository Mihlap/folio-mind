# Посещаемость: как посмотреть

Счётчики показывают только успешные **регистрации по email** и **входы по email с паролю**.
Регистрация по телефону, magic-link и через внешние сервисы не учитываются.

Данные обезличенные: в таблице хранятся тип события, дата и внутренние идентификаторы.
Адрес почты и IP-адрес не записываются.

## Важно знать заранее

Счётчики стартуют с нуля в момент установки метрик на сервер. У вас в таблице пока пусто,
и это нормально: числа появятся после первых регистраций и входов. Хотите убедиться,
что счётчик реагирует, — зарегистрируйтесь на сайте через обычную форму, потом повторите
команду из шага 4: `registrations` станет 1.

## Путь 1. На сервере, по шагам

Это проверенный способ для боевого сервера. Каждую команду вводите отдельно, Enter после
каждой. Не вставляйте всё одной длинной строкой: при вставке в SSH-окно она рвётся.

**Шаг 1. Подключиться**

```bash
ssh root@ваш-сервер
```

**Шаг 2. Перейти в папку проекта**

```bash
cd /root/pdf
```

**Шаг 3. Положить токен в переменную**

```bash
TOKEN=$(grep AUTH_METRICS_TOKEN apps/server/.env.prod | cut -d= -f2-)
```

Команда ничего не выведет — это нормально, она просто запоминает токен. Посмотреть его
значение можно отдельно:

```bash
grep AUTH_METRICS_TOKEN apps/server/.env.prod
```

**Шаг 4. Получить счётчики**

```bash
curl -s -H "Authorization: Bearer $TOKEN" "http://127.0.0.1:3001/metrics/auth?days=30"
```

Выведется JSON с полями `registrations`, `logins`, `activeUsers` и `byDay`. Длинный ответ
можно укоротить, чтобы не листать:

```bash
curl -s -H "Authorization: Bearer $TOKEN" "http://127.0.0.1:3001/metrics/auth?days=7" | head -c 200
```

**Шаг 5. Выдать разовую ссылку для браузера**

```bash
curl -s -X POST -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{}' "http://127.0.0.1:3001/metrics/auth/share?days=30"
```

В ответе будет поле `url` — это готовая страница со счётчиками. Откройте его в браузере.
Адрес будет на `127.0.0.1`, поэтому в браузере на своём компьютере он не откроется:
замените `127.0.0.1` на адрес сервера. Если порт 3001 закрыт firewall, попросите
администратора открыть его или пробросить через Caddy.

Срок жизни ссылки — 24 часа, задаётся на сервере.

**Про `node` и `psql`**

На сервере их нет, стоят только docker и curl. Поэтому `node tools/metrics-auth.mjs`
и `psql` на сервере не сработают — это нормально, используйте `curl` выше.

## Путь 2. С рабочего компьютера

Если API доступен снаружи, удобнее из домашней папки проекта:

```powershell
$env:AUTH_METRICS_TOKEN="ТОКЕН"
$env:API_URL="https://api.ваш-домен.ru"
pnpm metrics:auth 30
```

Печатает период, итоги и таблицу по дням, ссылку не создаёт.

С `--share` дополнительно печатается разовая ссылка:

```powershell
$env:SHARE_HOURS=2      # дать доступ на два часа вместо суток
pnpm metrics:auth 30 --share
```

Срок задаётся от часа до недели. Значение `days` в команде задаёт период счётчиков
в ссылке, а не срок жизни.

Если порт 3001 снаружи закрыт, этот способ не подойдёт — берите путь 1.

## Путь 3. Через Swagger

Swagger UI с этими эндпоинтами — на `http://localhost:3001/docs` (или на домене API).
Найдите `GET /metrics/auth`, нажмите **Try it out**, впишите токен в поле **Authorization**
в формате `Bearer <ТОКЕН>` и нажмите **Execute**.

Разовая ссылка через Swagger: `POST /metrics/auth/share`, в поле **Authorize** — тот же токен.

## Откуда брать токен

`AUTH_METRICS_TOKEN` — это фактически пароль от всей статистики проекта.
Локально он лежит в `apps/server/.env`, на сервере — в `apps/server/.env.prod`.

Если переменной нет, любой запрос к `/metrics/auth` вернёт 401. Это ожидаемо, а не поломка.

Сгенерировать новый:

```bash
openssl rand -hex 32
```

## Сколько хранятся данные

События не копятся бесконечно. Сервер раз в сутки удаляет записи старые 12 месяцев,
поэтому таблица `AuthEvent` остаётся небольшой. Срок совпадает с политикой
конфиденциальности (раздел 5).

Поменять срок можно переменной окружения `AUTH_EVENT_RETENTION_DAYS` (в днях):

```bash
AUTH_EVENT_RETENTION_DAYS=90   # хранить три месяца вместо года
```

Значение по умолчанию — `365`. Ноль, отрицательные и нечисловые значения
игнорируются, чтобы уборка не отключилась случайно.

Служебные настройки (обычно менять не нужно):

| Переменная                             | По умолчанию | Смысл                                    |
| -------------------------------------- | ------------ | ---------------------------------------- |
| `AUTH_EVENT_RETENTION_DAYS`            | `365`        | сколько дней хранить события             |
| `AUTH_EVENT_SWEEP_INTERVAL_HOURS`      | `24`         | как часто запускать уборку               |
| `AUTH_EVENT_SWEEP_START_DELAY_MINUTES` | `10`         | пауза перед первым запуском после старта |

Проверить, что уборка работает: в логах сервера появится строка
`[auth-metrics] retention run finished` с числом удалённых записей.

## Кого это касается

Ссылка по умолчанию открыта любому, кому вы её отправили. Это удобно, но помните:
разовый доступ не отзывается по звонку, истечёт только по сроку. Если нужен
закрытый доступ, заведите токен и раздавайте его конкретным людям.

Сбор посещаемости описан в политике конфиденциальности: раздел 2 (какие данные),
раздел 3 (правовое основание) и раздел 5 (срок хранения — до 12 месяцев).
