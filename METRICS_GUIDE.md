# Как посмотреть посещаемость

Этот файл объясняет, как узнать, сколько людей заходило в РазУм и сколько зарегистрировалось.
Если что-то не получается — идите по шагам и делайте их по одному.

Сразу скажу главное: **счётчики показывают ноль и это нормально.** Они начали собираться
только после установки, и в таблицу пишется всё новое. Старых данных там нет, взять их
неоткуда. Чтобы увидеть не ноль, достаточно один раз зарегистрироваться или войти.

## Что вообще считается

Только два события:

- человек зарегистрировался по email;
- человек вошёл по email и паролю.

Что не считается: вход по телефону, вход по ссылке из письма, вход через Google и другие
внешние сервисы. Если эти способы появятся, счётчик для них останется нулевым.

Ни адресов почты, ни IP-адресов в счётчиках нет. Записывается только: что произошло,
когда и внутренний номер пользователя. Посмотреть чью-то активность по таким данным
невозможно.

## Способ 1. Посмотреть на сервере

Этот способ надёжнее остальных, потому что сервер доступен всегда.

### Шаг 1. Откройте окно сервера

Нажмите на клавиатуре клавиши `Win`, напишите `PowerShell`, нажмите Enter.
В открывшемся чёрном окне введите:

```bash
ssh root@ваш-сервер
```

и нажмите Enter. Если спросит пароль — введите его и нажмите Enter.

Правильно подключились — увидите приглашение с решёткой на конце, например
`root@server:~#`.

### Шаг 2. Перейдите в папку проекта

Введите эту строку и нажмите Enter:

```bash
cd /root/pdf
```

Ничего не произойдёт, строка просто сменится. Это нормально.

### Шаг 3. Скажите окну, где токен

Введите и нажмите Enter:

```bash
TOKEN=$(grep AUTH_METRICS_TOKEN apps/server/.env.prod | cut -d= -f2-)
```

Окно ничего не напечатает — так и должно быть. Вы просто сказали окну, где лежит
пароль от статистики, и оно его запомнило, чтобы дальше не вводить руками.

### Шаг 4. Посмотрите цифры

Введите и нажмите Enter:

```bash
curl -s -H "Authorization: Bearer $TOKEN" "http://127.0.0.1:3001/metrics/auth?days=30"
```

Через пару секунд появится одна длинная строчка в фигурных скобках. Это результат.
Внутри есть:

- `registrations` — сколько человек зарегистрировалось;
- `logins` — сколько раз входили;
- `activeUsers` — сколько разных людей входило;
- `byDay` — те же числа по дням, слева направо.

Если строчка слишком длинная и неудобно искать, есть короткая версия:

```bash
curl -s -H "Authorization: Bearer $TOKEN" "http://127.0.0.1:3001/metrics/auth?days=7" | head -c 200
```

Она покажет только начало, этого хватит, чтобы увидеть главные числа.

### Шаг 5. Посмотрите таблицей, без скобок

В JSON искать неудобно. Есть готовая команда, которая печатает числа таблицей.
Токен в неё вводить не нужно, она берёт его сама. Введите и нажмите Enter:

```bash
bash tools/metrics-table.sh 30
```

Число в конце — это сколько дней показать. Можно заменить на любое другое.

Выведется вот так:

```
Период: 2026-09-02 ... 2026-10-01
Регистрации: 12
Входы:       30
Активные:    12

День         Регистрации   Входы
2026-10-01             3      8
2026-10-02             9     22
```

Дни, где ничего не было, пропускаются. Если не было ни разу, появится строка
`(пока нет ни регистраций, ни входов)`.

### Шаг 6. Сделайте ссылку, чтобы посмотреть в браузере

Иногда удобнее не читать JSON, а открыть красивую страницу. Введите и нажмите Enter:

```bash
curl -s -X POST -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{}' "http://127.0.0.1:3001/metrics/auth/share?days=30"
```

В ответе найдите поле `url` — это готовая ссылка. Выглядит она так:

```
http://127.0.0.1:3001/metrics/auth/share/m:...:....abc?days=30
```

Скопируйте её, вставьте в браузер и нажмите Enter. Откроется страница: три больших
числа сверху и таблица по дням снизу.

Ссылка живёт сутки, потом сама перестаёт работать. Поменять срок нельзя.

### Если что-то не получилось

**`command not found`** — надо понять, какая именно команда. Обычно это
значит, что вы не в папке проекта. Вернитесь к шагу 2 и попробуйте снова.

**`No such file or directory`** — то же самое, вы не там. Шаг 2.

**Вместо цифр ошибка про 401** — окно забыло токен, потому что вы открыли новое
SSH-соединение. Пройдите шаг 3 заново.

**Ссылка не открывается в браузере** — так и должно быть. В ссылке адрес `127.0.0.1`,
это значит «тот же самый компьютер». В браузере на вашем рабочем компьютере она не
откроется. Чтобы открыть, замените `127.0.0.1` на адрес вашего сервера. 

**Всё равно нули** — скорее всего, после установки метрик ещё никто не заходил.
Зарегистрируйтесь на сайте через обычную форму и повторите шаг 4: в `registrations`
должно появиться 1.

## Способ 2. С рабочего компьютера

Удобно, если сервер виден из интернета по домену. В своей папке проекта на компьютере:

```powershell
$env:AUTH_METRICS_TOKEN="ТОКЕН"
$env:API_URL="https://api.ваш-домен.ru"
pnpm metrics:auth 30
```

Здесь `AUTH_METRICS_TOKEN` надо вставить в кавычки вручную, а не доставать командой
grep. Токен можно посмотреть на сервере:

```bash
grep AUTH_METRICS_TOKEN apps/server/.env.prod
```

Команда напечатает строку вида `AUTH_METRICS_TOKEN=7e15...`. Всё после знака `=` —
это токен, копируйте только его, без слова `AUTH_METRICS_TOKEN=`.

Чтобы сразу получить ссылку, добавьте в конце команды `--share`:

```powershell
pnpm metrics:auth 30 --share
```

Способ не сработает, если порт 3001 на сервере закрыт для внешних подключений.
Тогда возвращайтесь к способу 1.

## Способ 3. Через страницу документации

Если сервер запущен у вас на компьютере, откройте в браузере:

```
http://localhost:3001/docs
```

Найдите строку `GET /metrics/auth`, нажмите на неё, потом кнопку **Try it out**.
В поле **Authorization** впишите токен в виде `Bearer 7e15...` — слово Bearer
обязательно, пробел после него тоже. Нажмите **Execute**, ответ появится ниже.

## Сколько хранятся эти данные

События не копятся вечно. Сервер раз в сутки вычищает всё старше 12 месяцев.
Записано это же и в политике конфиденциальности, раздел 5, — так что обещание
в документе и реальное поведение совпадают.

Если хотите хранить дольше или меньше, это настраивается одной настройкой,
но менять её без нужды не стоит.

## Про безопасность

Токен — это, по сути, пароль от всей статистики проекта. Кто его знает, тот видит
все цифры. Поэтому:

- не пересылайте токен в чатах и письмах, тем более в общих;
- не вставляйте его в код и не добавляйте в репозиторий;
- если случайно засветился — смените его и перезапустите сервер.

Разовая ссылка из шага 5 слабее токена: она открывает страницу со счётчиками, но
ничего не позволяет менять. Удобно показать коллеге. Заодно имейте в виду: ссылка
открыта тому, кому вы её отправили, и отозвать её нельзя — она просто истечёт через
сутки. Если нужен закрытый доступ, делитесь токеном с конкретными людьми.

## Если хочется проверить, что счётчик вообще живой

Самый быстрый способ: зарегистрироваться на сайте через обычную форму, потом
повторить шаг 4. `registrations` должен стать 1. Это занимает минуту и сразу даёт
уверенность, что механика работает, а не просто молчит.
