# Посещаемость: как посмотреть

Счётчики показывают только успешные **регистрации по email** и **входы по email и паролю**.
Регистрация по телефону, magic-link и через внешние сервисы не учитываются.

Данные обезличенные: в таблице хранятся тип события, дата и внутренние идентификаторы.
Адрес почты и IP-адрес не записываются.

## Быстрый способ: разовая ссылка

Самый простой путь для «показал коллеге и забыл» — одна команда, которая печатает и цифры, и ссылку.

```powershell
$env:AUTH_METRICS_TOKEN="ТОКЕН"
pnpm metrics:auth 30 --share
```

Ссылка открывается в браузере как обычная страница: три счётчика и таблица по дням.
Через сутки она перестаёт работать сама, продлевать ничего не нужно. Каждая такая ссылка
одноразовая по смыслу: срок задан при выдаче, отозвать её отдельно нельзя.

Срок задаётся переменной окружения, от часа до недели:

```powershell
$env:SHARE_HOURS=2      # дать доступ на два часа
pnpm metrics:auth 30 --share
```

Значение `days` в команде задаёт период счётчиков в ссылке, а не срок жизни.

## Если нужно просто посмотреть, не выдавая ссылку

```powershell
$env:AUTH_METRICS_TOKEN="ТОКЕН"
pnpm metrics:auth 30
```

Печатает период, итоги и таблицу по дням в терминале, ссылку не создаёт.

Для прода задайте адрес API:

```powershell
$env:API_URL="https://api.ваш-домен.ru"
$env:AUTH_METRICS_TOKEN="ТОКЕН"
pnpm metrics:auth 30
```

## Через API напрямую

Выдать разовую ссылку:

```bash
curl -X POST "http://localhost:3001/metrics/auth/share?days=30" \
  -H "Authorization: Bearer $AUTH_METRICS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"hours":24}'
```

Ответ содержит `url` (его и отправляете), `expiresAt` и `token`.

Получить сырые цифры:

```bash
curl -H "Authorization: Bearer $AUTH_METRICS_TOKEN" \
  "http://localhost:3001/metrics/auth?days=30"
```

Swagger UI с этими эндпоинтами — на `http://localhost:3001/docs`.

## Откуда брать токен

`AUTH_METRICS_TOKEN` — это фактически пароль от всей статистики проекта.
Локально он лежит в `apps/server/.env`, на сервере — в `apps/server/.env.prod`.

Если переменной нет, любой запрос к `/metrics/auth` вернёт 401. Это ожидаемо, а не поломка.

Сгенерировать новый:

```bash
openssl rand -hex 32
```

## Сколько хранятся данные

События не копятся бесконечно. Сервер раз в сутки удаляет записи старше 12 месяцев,
поэтому таблица `AuthEvent` остаётся небольшой. Срок совпадает с политикой
конфиденциальности (раздел 5).

Поменять срок можно переменной окружения `AUTH_EVENT_RETENTION_DAYS` (в днях):

```bash
AUTH_EVENT_RETENTION_DAYS=90   # хранить три месяца вместо года
```

Значение по умолчанию — `365`. Ноль, отрицательные и нечисловые значения
игнорируются, чтобы уборка не отключилась случайно.

Служебные настройки (обычно менять не нужно):

| Переменная                             | По умолчанию | Смысл                                    |
| -------------------------------------- | ------------ | ---------------------------------------- |
| `AUTH_EVENT_RETENTION_DAYS`            | `365`        | сколько дней хранить события             |
| `AUTH_EVENT_SWEEP_INTERVAL_HOURS`      | `24`         | как часто запускать уборку               |
| `AUTH_EVENT_SWEEP_START_DELAY_MINUTES` | `10`         | пауза перед первым запуском после старта |

Проверить, что уборка работает: в логах сервера появится строка
`[auth-metrics] retention run finished` с числом удалённых записей.

## Кого это касается

Ссылка по умолчанию открыта любому, кому вы её отправили. Это удобно, но помните:
разовый доступ не отзывается по звонку, истечёт только по сроку. Если нужен
закрытый доступ, заведите токен и раздавайте его конкретным людям.

Сбор посещаемости описан в политике конфиденциальности: раздел 2 (какие данные),
раздел 3 (правовое основание) и раздел 5 (срок хранения — до 12 месяцев).
