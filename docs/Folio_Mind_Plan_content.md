# Folio Mind — план проекта

## 1. Цель проекта

Folio Mind — это не просто просмотр PDF в браузере. Это платформа для полного цикла работы с документами: загрузка, хранение, просмотр, правки, конвертация, подпись, аудит и помощь искусственного интеллекта.

По охвату задач ориентир — класс решений вроде Adobe Acrobat, но с встроенным ИИ, которого у привычных PDF-редакторов нет в таком виде: проверка договоров на риски, поиск противоречий, подсказки по правкам, сравнение с внутренними шаблонами и регламентами, чат по документу.

Позиционирование: отдельный продукт с возможностями уровня Acrobat и рабочим процессом, заточенным под ИИ. Юридически и по бренду — свой продукт; технически — надёжная работа с PDF, конвертация и подпись.

Первая версия (v1) сфокусирована на одном сценарии: пользователь загружает договор, просматривает его, запускает ИИ-проверку рисков, получает отчёт и при необходимости уточняет детали в чате. Остальные функции наращиваются по этапам 0–4.

Важный принцип: ИИ предлагает черновики и замечания; подписать, отправить или опубликовать документ можно только после явного действия пользователя. Все ключевые шаги фиксируются в журнале.

Собственный PDF-движок не разрабатываем — используем PDF.js, pdf-lib, qpdf и Ghostscript; разрабатываем интерфейс, права, версии, хранилище S3 и слой ИИ.

## 2. Основные возможности

Базовый контур:

- Просмотр: страницы, масштаб, миниатюры, поиск по тексту
- Сборка и правки: слияние и разбиение PDF, работа со страницами, водяные знаки
- Формы в PDF — поэтапно
- Конвертация PDF и Office, изображения — в фоне
- Подпись: сначала визуальная, затем усиленная (отдельный юридический трек)
- Версии документов, права доступа, журнал действий

Слой ИИ:

- Аудит: риски, противоречия, пропуски разделов
- Предложения правок с подтверждением человеком
- Перефразирование и единый стиль терминов
- Извлечение дат, сумм, сторон договора
- Чат по документу и сверка с базой шаблонов (RAG)

Сценарий для архитекторов (буклеты и презентации):

Типовой документ — буклет с большим числом изображений (рендеры, планы, фото). Задача — убрать цикл «скачай PDF → сожми → отправь в мессенджер» и вести объект как проект, а не как один файл в чате.

Базовый макет (фаза 2b):

- Обрезка фотографий и позиционирование картинок на листе
- Линейки, направляющие, сетка; заливки с прозрачностью и градиентами
- Сжатие при выгрузке: пресеты «для почты», «для печати», «без сжатия»
- Ссылка для заказчика: просмотр в браузере, комментарии, без обязательного скачивания исходника

Удобство для бюро (тот же трек, поэтапно):

- Проект объекта: несколько PDF, именованные версии, сравнение «было / стало»
- Медиатека рендеров и фото — вставка в буклет без повторной загрузки с диска
- Шаблоны бюро: логотип, поля, типовые развороты
- Страницы: перестановка, дублирование, колонтитулы; режим презентации на встрече
- Согласование: watermark «черновик», статусы «на согласовании / утверждено», уведомления о комментариях
- Лёгкий ИИ: подписи к картинкам, черновик титульника, поиск по материалам проекта

Позже (фазы 3–4): экспорт страниц в JPG, чеклист качества перед печатью (DPI); фото с телефона на объекте и офлайн-просмотр актуального буклета.

Не обещаем замену AutoCAD, InDesign или одновременное редактирование «как в Google Docs» — фокус на PDF-буклете и согласовании с заказчиком.

## 3. Платформы

- Веб в браузере — один интерфейс на телефон, планшет и компьютер
- Android — установочное приложение APK или AAB на том же React-коде (Capacitor)
- PWA — установка на домашний экран без магазина
- iOS — браузер, PWA или приложение через Capacitor при необходимости
- Windows, macOS, Linux — только браузер, без отдельной программы .exe

## 4. Архитектура и технологии

Клиент: React, TypeScript, Vite, Redux Toolkit, RTK Query, React Router, Tailwind CSS, PDF.js для просмотра.

Сервер: Fastify, Prisma, PostgreSQL, Redis, BullMQ, S3 (MinIO в разработке), OpenTelemetry.

PDF: PDF.js и pdf-lib на клиенте; qpdf и Ghostscript на worker; отчёты — @react-pdf/renderer на сервере.

ИИ: GigaChat или YandexGPT — выбор заказчика при установке.

Разработка: монорепозиторий pnpm и Turborepo, Docker Compose, CI — GitHub Actions.

Производительность при росте числа пользователей (заложено в архитектуру):

- Быстрый API только для прав, метаданных и ссылок на файлы; тяжёлая работа с PDF — в фоне (worker), не в браузере и не в долгом HTTP-запросе.
- Загрузка и скачивание файлов напрямую в облачное хранилище (S3), без прогона больших PDF через сервер приложения.
- Просмотр: миниатюры страниц из хранилища и CDN; полный рендер в браузере — только для видимых страниц, без подвисаний на толстых буклетах.
- ИИ (саммари, чат): очередь и кэш по версии документа, лимиты на организацию; API не «висит» в ожидании ответа модели.
- Масштабирование: несколько экземпляров API и worker, лимиты задач на клиента, мониторинг очередей и времени ответа (OpenTelemetry).

## 5. Структура системы

- API — авторизация, права, загрузки, ссылки на файлы, ИИ
- Worker — превью страниц, извлечение текста, тяжёлая конвертация
- S3 — файлы PDF, превью, отчёты, временные данные обработки
- PostgreSQL — пользователи, документы, версии, аудит
- Redis — фоновые задачи и кэш

## 6. Хранение данных

Файлы и всё объёмное — только в S3. В PostgreSQL — описания: владелец, версия, ссылка на файл, размер, хеш, статус, журнал. Сам PDF в базу не кладём.

Каталоги в S3: originals (исходные PDF), previews (миниатюры), processing (временные файлы), exports (отчёты), rag-sources (шаблоны для ИИ). Большие файлы загружаются напрямую в S3 по временной ссылке.

## 7. Функции ИИ

- Краткое содержание документа
- Анализ рисков и ошибок
- Чат по документу с опорой на текст файла
- Структурированные предложения правок (принять или отклонить)
- Сверка с шаблонами и регламентами (RAG)
- Экспорт отчёта проверки

## 8. Этапы разработки

Фаза 0: окружение, база данных, вход в систему, каркас кода, правила производительности.

Фаза 1: загрузка PDF, просмотр, превью, ИИ через очередь, базовая проверка под нагрузкой.

Фаза 2: правки PDF, сравнение версий, RAG по регламентам.

Фаза 2b: буклеты — макет, проект и медиатека, шаблоны, согласование с заказчиком, сжатие.

Фаза 3: конвертация, формы, подпись, экспорт буклетов (JPG страниц, контроль DPI, PDF/A по запросу).

Фаза 4: адаптивный веб, PWA, APK; фото с объекта и офлайн-просмотр буклета.

Корпоративный SSO, on-prem и одновременное редактирование «как в Google Docs» — вне текущего плана; асинхронные комментарии и ссылка на просмотр — в фазе 2b.

## Риски и ограничения

- ИИ может ошибаться в юридических текстах — нужны дисклеймер и подтверждение человеком
- PDF нельзя бесконечно править как Word — в интерфейсе показываем ограничения
- Контроль расходов на ИИ — кэш текста и лимиты
- Проверка лицензий PDF и шрифтов до коммерческого запуска
- Тесты на разных браузерах Android (WebView)
- Ожидание уровня Photoshop/InDesign — в первых версиях только PDF-буклет с картинками, не полиграфическая допечатка
- Зависания на очень больших буклетах — снижаем превью, CDN, фоновую обработку и лимиты тяжёлых операций
