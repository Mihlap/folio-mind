## 1. Цель проекта

**Folio Mind** — это не просто просмотр PDF в браузере. Это платформа для полного цикла работы с документами: загрузка, хранение, просмотр, правки, конвертация, подпись, аудит и помощь искусственного интеллекта.

По охвату задач ориентир — класс решений вроде **Adobe Acrobat**, но с встроенным ИИ, которого у привычных PDF-редакторов нет в таком виде: проверка договоров на риски, поиск противоречий, подсказки по правкам, сравнение с внутренними шаблонами и регламентами, чат по документу.

**Позиционирование:** отдельный продукт с возможностями уровня Acrobat и рабочим процессом, заточенным под ИИ. Юридически и по бренду — свой продукт; технически — надёжная работа с PDF, конвертация и подпись.

**Первая версия (v1)** сфокусирована на одном сценарии: пользователь загружает договор, просматривает его, запускает ИИ-проверку рисков, получает отчёт и при необходимости уточняет детали в чате. Остальные функции наращиваются по этапам 0–4.

**Важный принцип:** ИИ предлагает черновики и замечания; подписать, отправить или опубликовать документ можно только после явного действия пользователя. Все ключевые шаги фиксируются в журнале.

**Собственный PDF-движок не разрабатываем** — используем PDF.js, pdf-lib, qpdf и Ghostscript; разрабатываем интерфейс, права, версии, хранилище S3 и слой ИИ.

## 2. Основные возможности

### Базовый контур

- **Просмотр:** страницы, масштаб, миниатюры, поиск по тексту
- **Сборка и правки:** слияние и разбиение PDF, работа со страницами, водяные знаки
- **Формы в PDF** — поэтапно
- **Конвертация** PDF ↔ Office, изображения — в фоне
- **Подпись:** сначала визуальная, затем усиленная (отдельный юридический трек)
- **Версии документов**, права доступа, журнал действий

### Слой ИИ

- Аудит: риски, противоречия, пропуски разделов
- Предложения правок с подтверждением человеком
- Перефразирование и единый стиль терминов
- Извлечение дат, сумм, сторон договора
- Чат по документу и сверка с базой шаблонов (RAG)

### Сценарий для архитекторов (буклеты и презентации)

Типовой документ — буклет с большим числом изображений (рендеры, планы, фото). Задача — убрать цикл «скачай PDF → сожми → отправь в мессенджер» и вести объект как проект, а не как один файл в чате.

**Базовый макет (фаза 2b):**

- Обрезка фотографий и позиционирование картинок на листе
- Линейки, направляющие, сетка; заливки с прозрачностью и градиентами
- Сжатие при выгрузке: пресеты «для почты», «для печати», «без сжатия»
- Ссылка для заказчика: просмотр в браузере, комментарии, без обязательного скачивания исходника

**Удобство для бюро (поэтапно):**

- Проект объекта: несколько PDF, именованные версии, сравнение «было / стало»
- Медиатека рендеров и фото — вставка в буклет без повторной загрузки с диска
- Шаблоны бюро: логотип, поля, типовые развороты
- Страницы: перестановка, дублирование, колонтитулы; режим презентации
- Согласование: watermark «черновик», статусы «на согласовании / утверждено», уведомления
- Лёгкий ИИ: подписи к картинкам, черновик титульника, поиск по материалам проекта

**Позже (фазы 3–4):** экспорт страниц в JPG, чеклист качества перед печатью (DPI); фото с телефона на объекте и офлайн-просмотр буклета.

**Не обещаем:** замену AutoCAD, InDesign или одновременное редактирование «как в Google Docs» — фокус на PDF-буклете и согласовании с заказчиком.

## 3. Платформы

| Платформа | Подход |
|-----------|--------|
| Веб | Один интерфейс на телефон, планшет и компьютер |
| Android | APK/AAB на том же React-коде (Capacitor) |
| PWA | Установка на домашний экран без магазина |
| iOS | Браузер, PWA или Capacitor при необходимости |
| Windows / macOS / Linux | Только браузер, без отдельной .exe |

## 4. Архитектура и технологии (кратко)

- **Клиент:** React, TypeScript, Vite, Redux Toolkit, RTK Query, PDF.js
- **Сервер:** Fastify, Prisma, PostgreSQL, Redis, BullMQ, S3
- **PDF:** PDF.js и pdf-lib на клиенте; qpdf и Ghostscript на worker
- **ИИ:** GigaChat или YandexGPT — выбор заказчика при установке
- **Разработка:** монорепо pnpm + Turborepo, Docker Compose

**Производительность:** быстрый API для прав и метаданных; тяжёлая работа — в worker; файлы — напрямую в S3; ИИ — через очередь и кэш.

## 5. Этапы разработки

| Фаза | Срок (ориентир) | Результат |
|------|-----------------|-----------|
| **0** | 3–6 нед. | Окружение, auth, каркас, MinIO |
| **1** | 2–4 мес. | Загрузка, viewer, превью, ИИ v0 |
| **2** | 3–6 мес. | Правки PDF, RAG, сравнение версий |
| **2b** | 3–6 мес. | Буклеты, макет, согласование с заказчиком |
| **3** | 4–8 мес. | Конвертация, формы, подпись, экспорт буклетов |
| **4** | 2–5 мес. | PWA, APK, фото с объекта, офлайн |

**Вне текущего плана:** корпоративный SSO, on-prem, совместное редактирование в реальном времени.

## 6. Риски и ограничения

- ИИ может ошибаться в юридических текстах — дисклеймер и подтверждение человеком
- PDF нельзя бесконечно править как Word — явные ограничения в UI
- Контроль расходов на ИИ — кэш и лимиты на организацию
- Проверка лицензий PDF и шрифтов до коммерческого запуска
- Большие буклеты — превью, CDN, фоновая обработка
